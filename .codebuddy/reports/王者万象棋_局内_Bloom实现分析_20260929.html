① 结论速览

1 次亮部提取（阈值+Karis 预滤波）
8 次降采样（逐级 ÷2，至 4×2）
7 次上采样（帐篷滤波+同级累加）
1 次全分辨率合成（场景+Bloom+自动曝光）
一句话结论：该 Bloom 是典型的 URP 风格"Karis 降采样金字塔 + 帐篷上采样累加" 的碎片着色器实现（Unity 特征：HLSLcc 命名 _uhlslcc_mtx4x4g_ColorMatrix、glslang 编译为 SPIR-V）。 全流程共 16 个全屏三角形 pass（对应 RenderDoc 里的 Colour Pass #3 ~ #18，事件 7063–7371，每个 pass 仅 1 次 3 索引绘制）， 加上 Colour Pass #19 开头的 1 次全屏合成（事件 7388），Bloom 相关 GPU 总耗时约 1.11 ms（Adreno 840 实测计数器）。

② 帧内定位与总体结构

截帧共 513 个 action / 437 次 draw。Bloom 链完全位于主场景渲染（Colour Pass #2，事件 8569）之后、UI 之前：

Colour Pass #2   (E8569)  ── 3D 场景渲染，输出场景颜色 80804 (2132×1198 RGBA8)
Colour Pass #3   (E7063)  ── Bloom 提取：80804 → 80811 (533×599)，软阈值 + Karis 6-tap 预滤波
Colour Pass #4~11(E7097~7273) ── 8 次降采样：533×599 → 533×299 → … → 4×2
Colour Pass #12~18(E7287~7371) ── 7 次上采样：4×2 → … → 533×299（最终 Bloom 纹理 347631）
Colour Pass #19  (E7388)  ── Bloom 合成：场景 80804 + Bloom 347631 → 17893 (2558×1438，含自动曝光)
                          └─ 之后 Pass #19/20 继续绘制 UI 与特效
金字塔"降-升"结构的判据：Pass #3~#11 的输出纹理 ID 单调递增（新分配的降采样链），Pass #12 起输出 ID 倒序回升（8×4 → 16×9 → … → 533×299）， 且上采样 shader 同时绑定两张纹理（低一级 + 同级降采样结果），是标准的逐级累加上采样（progressive additive upsample）。
分辨率注记：场景缓冲 80804 为 2132×1198（16:9 横屏），合成输出 17893 为 2558×1438（≈1.2× 上采样），最终经 8504/8563 两次全屏 blit 走 1440×2560 肖像后缓冲上屏。 Bloom 基础分辨率 533×299 = 场景分辨率的 1/4（2132/4=533，1198/4≈299）。提取 pass 一步从 2132×1198 直接到 533×599（水平 ÷4、垂直 ÷2，与 shader 内 3×2 采样脚印 4×2 texel 完全对应）。

④ 各阶段 Shader 算法分析

所有 Bloom pass 均为单个全屏三角形（glDrawElements 3 索引），SPIR-V 由 glslang 11 生成（GLES 的 GLSL→SPIR-V 路径），uniform 带 HLSLcc 前缀（_uu_* / _uhlslcc_*），可判定为 Unity URP 定制版 Bloom。

4.1 亮部提取（PS 57737 @ E7063）

要点：6 tap Karis 加权（3×2 采样脚印，对应 ÷4×÷2 降采样）+ URP 式软阈值（soft-knee），并顺带完成自动曝光、色彩矩阵换算。常量：_u_BloomSrcTex_TexelSize、_u_BloomSrcUvScale、_u_Threshold(vec4)、_u_Params(vec4)、_u_ExposureParams、_u_PostExposure、_ug_ExposureScale、_uhlslcc_mtx4x4g_ColorMatrix。 
// 伪代码（由 SPIR-V 反推）
const float2 OFFS[6] = {(-2,-1),(0,-1),(2,-1),(-2,1),(0,1),(2,1)};  // ×texelSize×uvScale
float3 sum = 0; float wsum = 0;
for (tap in OFFS) {
    float3 c = tex(_u_BloomSrcTex, uv + tap);          // 6 次显式 ImageSampleExplicitLod
    float  l = dot(c.rgb, {0.2125, 0.7154, 0.0721});   // Rec.709 亮度
    float  w = 1.0 / (l + _u_Params.y);                // Karis 权重
    sum += c * w;  wsum += w;
}
float3 col = clamp(sum / wsum, 0, 1);
col = col / (1.019 - col) * 0.155;                      // filmic 段（结合 alpha 的 mask 计算）
col *= _u_ExposureParams.xxx;                           // 自动曝光（+ ColorMatrix / PostExposure 分支）
// ---- URP 标准软阈值 ----
float br = max(col.r, max(col.g, col.b));
float soft = clamp(br - _u_Threshold.y, 0, _u_Threshold.z); // knee
soft = soft * soft * _u_Threshold.w;
float contribution = max(soft, br - _u_Threshold.x) / max(br, 1e-4);
o = max(col * contribution, 0);                         // 最终取正值

4.2 降采样（PS 57730 @ E7097~E7273，8 次复用）

要点：5-tap 加权盒滤波：4 个对角 tap（±1,±1）+ 中心 tap（权重 ×4），每个 tap 同样做 1/(luma + _u_Params.y) 的 Karis 式加权后归一化。GPU 成本随分辨率减半快速衰减。 
const float2 DIAG[4] = {(-1,-1),(1,-1),(-1,1),(1,1)};  // ×texelSize×uvScale
float3 sum = 0; float wsum = 0;
for (d in DIAG) { c = tex(src, uv+d); w = 1/(luma(c)+_u_Params.y); sum += c*w; wsum += w; }
c = tex(src, uv);                    // 中心
w = 1/(luma(c)+_u_Params.y);
sum += c * w * 4;  wsum += w * 4;    // 中心权重 ×4
o = sum / wsum;

4.3 上采样（PS 57733 @ E7287~E7371，7 次复用）

要点：双输入（binding0 = 低一级纹理做帐篷滤波；binding1 = _u_BloomTex 同级降采样结果直接累加）。8 tap 帐篷核，偏移 ×0.5×_u_SampleScale×texelSize，权重 1/2/2/1 型，总和 ×1/12 —— 即 COD:AW 式 dual-filter 上采样 + 金字塔累加。 
float s = 0.5 * _u_SampleScale * texelSize;            // 缩放后的采样步长
// 低一级纹理上的 8 个 tap（含权重 ×2 的 3 个）：
taps = { uv+(-2s,0):1, uv+(-1s,+1s):2, uv+(0,+2s):1, uv+(+2s,0):1,
         uv+(+1s,0):2, uv+(+1s,-1s):2, uv+(0,-2s):1, uv+(-1s,0)... }  // 权重合计 12
float3 up = (Σ tap×weight) * 0.0833;                   // = ×1/12
o = up + tex(_u_BloomTex, uv);                         // 同级降采样结果累加（金字塔融合）

4.4 合成（PS 60023 + VS 60022 @ E7388）

要点：像素着色器极简（两采样 + MAD），自动曝光在顶点着色器里完成（读 16×16 曝光纹理 15966，uniform _u_AutoExposureEnable/_u_ExposureScale/_u_PostExposure，经 UV1 插值传给 PS）。输出上限 clamp 16（HDR 余量）。 
// PS：_u_BlitTex = 场景 80804（2132×1198），_u_BloomTex = 最终 Bloom 347631（533×299）
float3 bloom = tex(_u_BloomTex, uv).rgb;
float3 scene = tex(_u_BlitTex, uv).rgb;
float3 o = (scene + bloom * _u_Bloom_Params.xxx) * _u_Bloom_Params.yzw; // 强度 + 颜色 tint
o = o * exposure;                                       // VS 计算的自动曝光（uv1 插值）
o = min(o, 16.0);                                       // HDR 上限
// 输出 → 17893 (2558×1438)，同时把场景 2132×1198 放大约 1.2×

⑦ 可借鉴的优化点（参照性质）

  • 裁剪低价值 mip：16×9 / 8×4 / 4×2 三级对视觉贡献极小（对应弥散半径 > 60% 屏宽的极暗光晕），却占 3 降 + 3 上共 6 个 pass（~0.11 ms 含固定开销）。减到 5 降 4 上即可省 ~0.1–0.15 ms。
  • RGBA8 → R11G11B10：整条金字塔为 RGBA8（LDR 量化），合成端却按 HDR 处理（clamp 16）。R11G11B10 无需 alpha 且带宽 −25%，可减轻提取/首降两个最贵金字塔 pass。
  • 合成 pass 拆分审视：合成既要采样全分辨率场景又要 1.2× 上采样写出 2558×1438（0.44 ms），把 Bloom 叠加合并进随后的放大 blit 或直接在 2132×1198 原生分辨率完成叠加，可省一次全分辨率写。
  • 阈值合并：提取 pass 已含曝光/色彩矩阵等多个分支；若阈值参数运行时不变，可把 soft-knee 常量化减少 ALU。
  • 相比终末地的 CS 共享内存方案，GLES 全屏三角形方案每 pass 固定开销更高（~14 μs 地板），在 pass 数多时 CS 合批（如一次 CS 完成 2~3 级降采样）收益明显。

⑧ 数据来源与取证方法

  • 截帧加载状态与帧统计：get_capture_status / get_frame_summary（513 actions，22 顶层 marker）。
  • 事件树与 pass 定位：get_draw_calls（Colour Pass #3~#18 各含 1 次 3 索引绘制，是识别 Bloom 链的直接线索）。
  • 输入/输出纹理关系：get_draw_call_details（16 张输出纹理 ID）+ get_pipeline_state（E7063/7097/7123/7287/7371/7388 的像素着色器绑定，含 _u_BloomSrcTex/_u_BloomTex/_u_BlitTex/_u_Threshold/_u_Bloom_Params 等 uniform 名）。
  • 纹理尺寸/格式/字节：get_texture_info（80804/80811/347631~347644/370905~370911/370906/370909/17893）。
  • 算法取证：get_shader_source（PS 57737 / 57730 / 57733 / 60023 的 SPIR-V 全文，glslang 11 生成；本文伪代码由其反推）。
  • 耗时：get_action_timings（Adreno 840 GPU 计数器，17 个事件逐条）。
  • 注：常量缓冲具体数值读取失败（MCP 端 GetConstantBuffer 属性缺失），阈值具体标量未取证；find_draws_by_resource 在 OpenGL 截帧下返回全量匹配（工具 bug），已改用逐事件管线状态确认。
