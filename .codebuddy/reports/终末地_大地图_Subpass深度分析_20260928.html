核心结论：该帧把植被深度预pass、GBuffer 填充、植被着色、延迟光照、特殊材质二次着色五步全部合并进一个 5-Subpass 超大 RenderPass（E2621–E4803，约 530 个 Draw）。这是教科书级的移动端 TBR/TBDR 渲染架构：深度与 GBuffer 全程驻留 tile 内存（on-chip），延迟光照通过 subpass 内依赖直接消费 GBuffer，完全避免了中间 attachment 在主存的往返。RenderDoc 顶层把它拆成 3 个标签（Depth-only Pass #4 / Colour Pass #9 / Colour Pass #10），容易误读为 3 个独立 RenderPass。

2. 背景：Vulkan Subpass 与移动端 TBR 架构

  • Tile-Based 渲染（TBR/TBDR）：移动端 GPU（Adreno/Mali/PowerVR）把屏幕切成小块 tile，光栅化与像素着色在高速 on-chip 内存中逐 tile 完成。RenderPass 边界决定了 tile 何时把结果写回主存（Store）、何时重新读入（Load）。
  • Subpass：同一 RenderPass 内的渲染阶段。规范保证先前 subpass 写入的 attachment 在后续 subpass 中以 input attachment（subpassLoad）读取时无需离开 tile 内存——这是 Vulkan 对 GBuffer 延迟渲染在移动端的原生支持，等价于 Metal 的 tile shader / 控制台上的 UAV barrier-free ping-pong。
  • 收益：一个 4MRT 的 GBuffer（本帧 1842×1036×4 张）若用传统"写回主存→再采样"的桌面式延迟管线，每个 attachment 要经历一次 Store + 一次采样 Load（约 4×7.6MB×2 的主存流量）；subpass 方案下这部分流量趋近于零，直接降低带宽与功耗——移动端帧耗时的第一制约因素。
  • 代价：整个 RenderPass 的所有 attachment 必须同时驻留（FBO 尺寸变大）；subpass 间自动插入依赖屏障，并行度受限于串行链。

3. 证据链：如何在 RenderDoc 中定位这个 5-Subpass RenderPass

#证据事件说明
1vkCmdBeginRenderPass(DS=Clear)E2621整个大 RenderPass 的唯一入口；DS=Clear 即 Subpass 0 的初始布局（深度在 RP 开始时清一次）
2vkCmdNextSubpass() => 1E3127Subpass 0（植被深度）结束 → 进入 Subpass 1（GBuffer）。两个事件之间没有任何 End/BeginRenderPass
3vkCmdNextSubpass() => 2E4563GBuffer → 植被着色
4vkCmdNextSubpass() => 3E4600植被着色 → 延迟光照
5vkCmdNextSubpass() => 4E4637延迟光照 → 特殊材质二次着色
6vkCmdEndRenderPass(C=Store, DS=Store)E4803唯一出口；颜色与深度在 RP 结束时一次性写回主存，供后续透明/后处理 pass 使用
识别技巧（qrenderdoc）：① Event Browser 搜索 NextSubpass；② 看 Event Browser 顶层标签——RenderDoc 会把每个 subpass 单独显示为 "Colour Pass #N" / "Depth-only Pass #N" 合成标签，相邻标签间没有 Begin/EndRenderPass 即属同一物理 RenderPass；③ Pipeline State 面板的 FBO/RenderPass 页显示当前 subpass 索引，且先前 subpass 的 attachment 会出现在绑定列表中。

5. Attachment 生命周期与流向

RenderPass E2621 → E4803（唯一一次 DS=Clear @begin，C=Store DS=Store @end）

126274 D24S8 ：SP0 写(清) → SP1 写 → SP2 写 → SP3 读(重建线性深度) → SP4 写 → Store（后续 Colour Pass #13/#14 以 DS=Load 继续使用同一深度）
126758：SP1 写 → SP2 写 → SP4 写（光照/特殊材质） → Store
126262：SP1 写 → SP2 写 → SP4 写 → Store
126279 RGBA8：SP1 写 → SP2 写 → SP3 读（input 消费） → 不再写 → Store
126282 RGBA8_SRGB：SP1 写 → SP2 写 → SP3 读（input 消费） → 不再写 → Store

外部输入（SP3 采样，RP 外资产）：126018 126021（2048² D16 CSM）· 126036（512² D32）· 7985 3D LUT · 34745
设计解读：126279/126282（albedo/材质参数类）在 SP1/SP2 写完后再无写入，纯粹作为 SP3 光照的输入——这是标准的"GBuffer 写入 → 光照读取"单向流，subpass 依赖链干净。126758/126262（光照/法线累加类）则贯穿 SP1/SP2/SP4 三次写入，SP4 收窄为 2MRT 正是为了只更新 HDR 颜色相关目标而不必绑满 4 个。

6. 该架构的收益评估（对照传统桌面式管线）

环节传统管线（独立 RenderPass）本帧 subpass 方案收益
GBuffer → 延迟光照4 张 attachment Store 到主存（≈30MB 写）→ 光照 pass 再采样（≈30MB 读）tile 内 input attachment 直读省约 60MB/帧主存流量（1842×1036×4B×4attachment 量级）

植被深度/着色分相需 2 个 RP（深度 RP + 着色 RP），深度中间写回SP0/SP2 与主流程同 RP植被 alpha-test 几何的深度与着色分离且零额外带宽
管线切换开销5 个 RP ≈ 5 次 Begin/End + 布局转换屏障1 个 RP，4 次 NextSubpass（驱动内轻量切换）降低 CPU 提交与驱动验证开销
工程评价：这是 Unity SRP 或自研引擎在移动端 Vulkan 上做 deferred 的正确姿势（对照 URP 的移动端 forward、或 HDRP 的桌面 deferred）。CSM 阴影图（126018/126021/126036）在 RP 外的 Compute Pass #1 中生成（帧首 28 次 CopyImage 即级联合并），SP3 只读——阴影与主 RP 的依赖切分同样干净。

7. 风险与优化空间

  • SP4 的 MRT 收窄（4→2）是亮点：特殊材质 pass 只绑 126758/126262，减少了无谓的 attachment 驻留。但 SP1/SP2 全程绑满 4MRT+Depth，若部分几何（如纯 alpha-test 植被）实际只写 2–3 个目标，可再拆子通道进一步收窄（代价是 RP 复杂度上升，需权衡）。
  • input attachment vs 采样纹理：SP3 的 PS 绑定列表里 GBuffer 以普通 sampled texture 形式出现（res18/res19/res20）。若驱动按普通采样处理（而非 subpassLoad 专用路径），在部分 Adreno 上仍会触发 tile 内回退。建议对着色器 SPIR-V 做 SubpassLoad 指令级确认（本报告未反汇编 SP3 的完整 SPIR-V，属待验证项）。
  • 串行链：SP0→SP1→SP2→SP3→SP4 是全串行依赖。SP4（水/反射）理论上只依赖 SP3 的光照结果，与 SP1 无数据依赖，若拆出独立 RP 与 SP3 并行提交，可提升队列并行度——但对单队列移动端 GPU 收益有限，属于低优先级。
  • 深度生命周期：126274 在 RP 结束时 DS=Store，被后续 Colour Pass #13/#14（DS=Load，透明层复用深度测试）消费——设计正确。但注意 E5321/E5330（合成/UI pass）又 DS=Clear 开了新深度，属正常分层。
  • 可移植性提示：该 5-Subpass 结构在 Mali（需要 subpass 数 ≤ 8 的 forward 混合限制）与 PowerVR（TBDR 原生受益最大）上行为不同；Adreno 的 flex render 对 subpass 依赖有自动优化。跨机型需验证 tile 驻留是否真正生效（ Snapdragon Profiler 的带宽计数器对比）。
