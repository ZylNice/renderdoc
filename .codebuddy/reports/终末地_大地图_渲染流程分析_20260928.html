核心结论（经逐 Pass SPIR-V 取证修正）： 帧首 Compute Pass #1（98 action）不是游戏逻辑——它是 RenderDoc 回放在 PC 端注入的 ASTC 纹理解码与资源初始内容还原（见 4.1 节），分析游戏帧耗时时应整体剔除； 真正的游戏前置工作是：Colour Pass #1–3 的预计算大气散射 LUT 链（transmittance → 多重散射 → 天空视景）、Compute Pass #2 的植被散布/风场数据生成、Colour Pass #4–7 的程序化贴图链，以及 Depth-only Pass #1–3 的阴影图渲染（聚光 512² D32 + CSM 2048² D16 ×2）——不存在独立的场景深度预 pass； 场景几何在单一 5-Subpass 超大 RenderPass（E2621–E4803）内完成深度写入（SP0/SP1，SP1 用 null PS）→ GBuffer 填充（SP2，4 MRT）→ 延迟光照（SP3）→ 特殊材质（SP4）； 后段为 Karis Bloom 金字塔 + 畸变合成 + UI。GPU 热点集中在 GBuffer/阴影阶段的中大网格与高实例数植被（overdraw 受限）。

4. 关键技术特征

4.1 帧首 Compute Pass #1 = RenderDoc 注入的 ASTC 解码（非游戏逻辑）

  • 决定性证据：Compute Pass #1 首个 dispatch（E76）的着色器（ResourceId::1590）是完整的 ASTC 解码器——函数名与结构一目了然：astcDecodeTexel、decodeEndpoints、decodeWeights、selectPartition、hash52（分区种子哈希）、buildBitmask、decodeTrit/decodeQuint（三/五进制权重解包），生成器标注 Shaderc over Glslang（与游戏侧 spiregg 不同源）。这是 RenderDoc 在不支持 ASTC 的 PC 上回放时注入的纹理解码工作。
  • 同 Pass 内 28×CopyImage + 10×CopyBufferToImage 是 RenderDoc 还原截帧时刻资源初始内容的回写。
  • 分析结论修正：Compute Pass #1 的 98 个 action 应整体从"游戏帧耗时"中剔除；帧首 GPU 开销（E76–E452 各 dispatch 约 0.002–0.033ms）属于回放工具成本，真机上不存在。
  • 游戏自身的 GPU-Driven 证据不变：GBuffer 主通道 VS（E3204）从 8.4MB SSBO（Buffer 1193）顶点拉取，配超大打包常量块（1312B×22 矩阵 / 3200B×139 float4）。

4.2 阴影图渲染：Depth-only Pass #1–3（原"深度预pass"误判修正）

  • 修正说明：初版将这三段当作场景深度预pass，经输出目标逐条核实，它们写的是阴影贴图而非场景深度：
    • DP1（E578–E677，21 Draw）→ 126036（512×512 D32）= 聚光/点光阴影，SP3 光照着色器 slot 0 绑定证实；
    • DP2（E679–E2083，~290 Draw）→ 126018（2048×2048 D16）= CSM 级联 1（近平行光）；
    • DP3（E2085–E2610，115 Draw）→ 126027（3072×2048 D16）= CSM 级联 2（远平行光，画幅更宽对应远距视锥）。
    取证：get_draw_call_details @ E586/E676/E691/E2094/E2101 的 depth_output 逐条核实；get_texture_info 确认格式与分辨率；E4604（SP3 光照）的资源绑定（res21=126018、res25=126021、slot0=126036）闭环验证。
  • 阴影渲染是该帧 Draw 数最重的部分之一（~426 Draw），且与后续 GBuffer 的几何高度重叠——属阴影投射器的常规代价。
  • DP1 的首个 Draw（E586）为全屏三角形 + DepthReplacing PS（126376）：采样高度纹理重排阴影深度——阴影图初始化/拷贝操作。
  • 不存在独立的场景深度预pass：场景深度直接在大 RenderPass 的 SP0（植被层，DS=Clear）与 SP1（主几何，null PS 写深度）中生成。

4.3 GBuffer：单一 5-Subpass 超大 RenderPass（Tiled-Subpass 架构）

  • 识别方法：Event Browser 中存在 4 条 vkCmdNextSubpass() => N 事件（E3127/E4563/E4600/E4637），且整个区间 E2621(BeginRenderPass, DS=Clear) → E4803(EndRenderPass, C=Store DS=Store) 之间没有任何 End/BeginRenderPass——即 "Depth-only Pass #4"、"Colour Pass #9"、"Colour Pass #10" 三个顶层标签（RenderDoc 对子通道的合成标记）实际是同一个物理 RenderPass 的 5 个 Subpass。
  • Subpass 0（E2621–E3126）：植被/实例层深度预pass（DS=Clear，119 Draw，1536×62 实例草丛收尾）。深度预pass被纳入同一 RenderPass，TBR 上避免 tile 卸载/重载。
  • Subpass 1（E3127–E4562）：GBuffer 主着色，写入 4 个 MRT + Depth（E3204 输出 ResourceId 126758/126262/126279/126282 + Depth 126274），主 GBuffer 格式 R11G11B10_FLOAT（1842×1036）——移动端友好的带宽优化格式。
  • Subpass 2（E4563–E4599）：8 Draw，植被二次着色（1536 索引 × 62 实例再次出现）。
  • Subpass 3（E4600–E4636）：9 个全屏 Draw，以 input attachment 方式在 RenderPass 内直接消费 GBuffer（光照/解析），避免 RenderPass 间切换与 tile 内存卸载，是典型的移动端 TBR/TBDR 优化手法。
  • Subpass 4（E4637–E4803）：~38 Draw，将 Subpass 1 中的最大网格子集（37839/33729/29655/22137/17331 索引等）重绘一遍，推测为水体/特殊材质的二次着色或平面反射采样层。

4.4 后处理链：Karis 亮部提取 Bloom（已通过反汇编确认）

  • Bright-Pass（E5263，CS=ResourceId::126477，SPIR-V 已确认）：着色器对每个像素取 4 个对角采样（偏移 (0.9,−0.4)/(−0.9,0.4)/(0.4,0.9)/(−0.4,−0.9)×texel scale），每个采样先做 NaN/Inf 防护（与 0x7F7FFFFF=FLT_MAX 比较），然后执行经典 Karis 软阈值亮部提取：maxc = max(r,g,b) → clamp(maxc − threshold, 0, knee) → softKnee × x²（平方软拐点）→ 归一化，并用亮度权重 1/(luma+1)（luma 系数 0.2126/0.7153/0.0722，即 Karis average 抗闪烁加权）做 4 tap 加权平均后写入。这是 ACES/CoD 风格的标准 Bloom 提取方案。
  • 金字塔混合（E5319，CS=ResourceId::126533，已确认）：着色器对低一级金字塔纹理做 ImageFetch、对高一级做 ImageSample，然后 FMix(fetch, sample, intensity) 写回——典型的 Bloom 降/升采样混合节点。整条链操作 1842×1036 → 921×518 → 461×259 的 R11G11B10 目标（ResourceId 126291/126294/126333），共 15 级 Dispatch。
  • 合成与色调映射（E5258，PS=ResourceId::126467，已确认）：最终合成并非简单叠加——着色器先从一张辅助纹理 ImageFetch UV 并计算 sign(uv−0.5)×(|uv|×2−1)² 形的 桶形畸变 UV（lens distortion），再采样场景+Bloom 合成纹理，用 3×3 邻域 min/max 钳制（ImageGather×4 + 邻域比较，防 Bloom/TAA 上采样溢色的 neighborhood clamp），随后执行色调映射（c/(1+c) Reinhard 型曲线 + 通道重排编码）输出。
  • 最终 blit（E5336，PS=ResourceId::28429）只是带 LOD 的简单纹理采样（把 1842×1036 RGBA8 场景色 126336 拷到 BackBuffer 1722），Bloom 合成发生在其上游的 E5258。1842×1036 ≈ 16:9，非标准分辨率，疑似动态分辨率缩放后的渲染目标。

4.5 Colour Pass #8：解析式高度雾/大气散射（修正原"SSAO"误判，已反汇编确认）

  • 修正说明：本报告初版将 Pass #8 标注为"SSAO/环境光吸收"，系仅凭"Clear+单全屏 Draw"形状的误判。E2618 像素着色器（PS=ResourceId::126392）反汇编确认其真实用途为解析式高度雾。
  • 证据一（零纹理采样）：SSAO 至少需采样深度图，但该 PS 的资源绑定为空（resources: []）——不读任何 GBuffer，纯数学计算。
  • 证据二（射线解析积分）：着色器从相机位置（uniforms7._child11.xyz）+ UV 构造视线射线，与雾高度平面求交（t=(h−camY)/dirY 型参数化）；对指数高度衰减密度做解析积分 (1−exp(−x))/x，并带数值稳定泰勒回退（0.6931=ln2、0.2402=(ln2)²/2）；Beer-Lambert 透射 exp(−scatter×dist×density)；双层雾（两组 exp2 衰减相加）。
  • 证据三（输出语义）：输出 RGB = 1−exp(−β·d)（内散射颜色）、A = 1−fogFactor（1−透射率），即标准的高度雾 inscatter/transmittance 对。另有 uint(FragCoord.x)==0 的逐列分支输出 255 量化散射色（疑似调试/打包混合用途）。
  • 架构含义：因不依赖 GBuffer，雾在 E2612（大 RenderPass 之前）预计算，光照阶段按需采样。Frostbite 风格的物理高度雾/远景大气。帧内未发现独立的 SSAO/GTAO pass——AO 可能折算进 SP3 延迟光照或环境 SH 中。

4.6 GBuffer 前置 Pass 逐段取证（本轮重分析）

  • Colour Pass #1（E461，PS 28422）→ 透射率 LUT：无纹理输入，纯数学：对每条视线做解析积分（双 exp 衰减层 + (1−e^(−x))/x 稳定形式），输出 exp(−Σ密度) 到 3386——Bruneton 式预计算大气散射的透射率 LUT。
  • Colour Pass #2（E470，PS 28424）→ 多重散射 LUT：采样 #1 的透射率 LUT，双 while 步进循环（到地表+到大气顶两段路径）× 0.0796（≈1/4π，各向同性相函数归一化）累加内散射，末尾做了二次多项式拟合封装（x², x³, x⁴ 项）输出到 3389——多重散射能量守恒 LUT。
  • Colour Pass #3（E479，PS 28426）→ 天空视景 LUT：采样前两张 LUT，沿视线步进并累计 Rayleigh（相位函数 3(1+cos²θ)/(16π) 的 0.0597 常数）+ Mie（HG 相位 (1−g²)/(4π(1+g²−2g·cosθ)^1.5)，12.5625=4π 印证），乘太阳色输出到 3383。
  • Compute Pass #2（E484–E535）：首个 dispatch（E484，CS 148398）是SSBO 计数器清零（写常量到槽位）；主体（如 E530，CS 4339）是植被/风场体素生成：从 SSBO 读散布点列表，按两级盒形范围（464m/208m 外层 + 29m/13m 内层 + 116m/52m 第三层）做密度衰减，采样 6 张 3D 噪声纹理（fract 平铺），并按 PackHalf2x16 打包写入实例数据 SSBO（126755）。其中的 0.0313≈1/32、256 灯数组遍历是 cluster 光照关联。这是后续 1536×62 草丛实例化的数据来源。
  • Colour Pass #4（E543，PS 160586）→ 光斑合成：8 个（xy=中心, z=缩放, w=强度）径向衰减 blob 叠加 + 噪声纹理采样，输出到 160577。疑为体积光锥/探针分布场。
  • Colour Pass #5（E552，PS 160589）→ 锐化：对 #4 输出做 4 邻域差分锐化（c + k×(c−neighbors/4) 型，含 0.4 半径圆形 vignette 掩膜），是 LUT 数据的对比度增强。
  • Colour Pass #6（E561，PS 160604）→ 法线生成：对 #5 结果做中心差分（±0.002 偏移两采样）求梯度，缩放后构造 (dx, dy, 1) 归一化，打包 N×0.5+0.5 到 RGB、高度到 A——高度场转法线图的标准操作。
  • Colour Pass #7（E575，PS 126372）：小工具 Pass，两纹理重采样重打包（R 取第二张 .y、G 取第一张 .x，带 UV 边界钳制）——数据格式转换。
  • Colour Pass #8（E2618）：解析式高度雾（见 4.5 节），与前述 LUT 共同构成完整大气渲染栈：预计算散射 LUT（#1–3）+ 解析高度雾（#8）。
  • Depth-only Pass #1–3：阴影图渲染（见 4.2 节），聚光 512² D32 + CSM 级联×2。
整体认知修正：GBuffer 之前的 12 个顶层 Pass 中，只有 Compute Pass #1 是 RenderDoc 注入（应从性能分析剔除）；其余 11 个均为游戏逻辑，分工为：大气 LUT 链（#1–3 色彩）→ 植被/风场数据（Compute #2）→ 程序化贴图（#4–7）→ 阴影图（Depth #1–3）→ 高度雾（#8）。不存在 Hi-Z、SSAO、场景深度预pass——初版基于 Pass 形状推断的结论全部作废，以本节反汇编证据为准。

4.7 GBuffer 后段 Pass 逐段取证（本轮重分析）

  • Colour Pass #11（E4811）→ 深度拷贝：PS 126458 是带 LOD 参数的纯采样 blit，读 GBuffer 深度 126274（D24S8）写 126285（R32_FLOAT，全分辨率）——把深度转成可自由采样的 float 纹理，供 SSR 等后续 pass 使用。
  • Colour Pass #12（E4820）→ Hi-Z 第一级：PS 132699 对深度做 4-tap NMax 池化（中心 + 右 + 下 + 右下取 max），输出 132437（R32_FLOAT，921×518 半分辨率）——max 语义确认这是 Hi-Z 保守深度金字塔的首级（而非均值降采样），供光线步进做遮挡粗判。
  • Colour Pass #13（E4831 等）→ SSR 屏幕空间反射：PS 132706 含 12 步光线步进循环：每步 4 个深度采样点做包围盒早退（Any(<eps) 命中判定 + 线性插值求精确交点），配 2D 抖动哈希（fract(dot(p,{0.0671,0.0058}))×52.9829）抗条带；读 RT0（HDR 场景色）、RT1（反射向量编码）、132437（Hi-Z）；输出到 139253（921×518 R11G11B10 半分辨率） + 132434。步进式 march + 邻域命中判定是标准 SSR 实现。
  • Colour Pass #14（E4906 等）→ 前向植被/透明 uber-shader：PS 160611（1652 个 SPIR-V id，全帧最大着色器之一）功能清单：cluster 光照（32 灯盒交集 + 位域遍历）、CSM 阴影比较采样（ImageSampleDrefExplicitLod）、反射探针（2DArray + LOD 偏置）、植被风场（6 张 3D 噪声纹理 fract 平铺 + 两级盒形衰减）、imposter 2DArray、高度雾/大气散射（与 Colour Pass #8 同源的 0.0597 Rayleigh 常数）、菲涅尔、Alpha 裁剪。写 126288 + 126262（反射向量 RT）。318/6 索引小 Draw 为粒子/特效。
  • Colour Pass #15（E5258）→ 解析+色调映射：桶形畸变 UV（sign(uv−0.5)×(|uv|×2−1)²）、3×3 邻域 min/max 钳制、Reinhard 型 c/(1+c)——已在前轮确认（4.4 节）。输出 126265。
  • Compute Pass #3：Karis Bloom 金字塔（4.4 节已确认）。
  • Colour Pass #16（E5327）→ 最终合成：PS 126537 是完整的后处理合成器，逐功能实锤：
    • 锐化：中心 − 4 邻域均值，增益限幅 ±0.1（防过冲）；
    • Bloom 叠加：读 Bloom 金字塔末端，Karis 软阈值曲线混合；
    • Vignette：径向 1−|uv−c|² 幂次衰减（pow）；
    • LUT 调色：Log2×0.3010（log10 化）→ 2D 图集式 LUT 双切片采样 + frac 插值——LogC 编码的 3D LUT 打包成 2D tile 的经典实现；
    • sRGB 编码：分段函数常数 12.9219 / 1.0547 / 0.0550 / 0.4167(=1/2.4) / 0.0031 与 sRGB EOTF 逐位吻合；
    • 胶片颗粒：位置哈希抖动（dot(uv,{171,231})×{0.0097,0.0141,0.0103} → fract → ±0.0039 幅值），de-banding 抖动。
    输出 126336（RGBA8 1842×1036）——最终 LDR 画面。
  • Colour Pass #17（E5336 + E5342 等）→ 上屏 + UI：E5336 纯 blit（28429）把 126336 拷入 BackBuffer 1722；后续 ~86 个小 Draw 是 UI（E5342，PS 28431：顶点色 ×255 量化还原、纹理采样、premultiply alpha、FMix 淡入淡出——标准 UGUI 式着色器）。
  • Copy/Clear Pass #1（E5620）：vkCmdCopyImageToBuffer 回读 BackBuffer——截图/水印/缩略图类功能，会阻塞帧间并行（见建议 5）。
后处理链全景（修正后）：深度拷贝(#11) → Hi-Z max 池化(#12) → SSR 半分辨率(#13) → 前向植被/透明(#14) → 畸变+邻域钳制+Reinhard(#15) → Karis Bloom 金字塔(Compute #3) → 锐化+Bloom+vignette+LUT 调色+sRGB+颗粒(#16) → blit 上屏(#17) + UI。与初版"透明层/色调映射前处理"的模糊标注相比，每一环均有反汇编或绑定级证据。

4.8 Bloom 实现的特殊优化（对比 Unity 内置实现）

结论：有，且是工程上相当激进的一组优化。该引擎的 Bloom 金字塔没有走光栅化全屏 pass，而是纯 Compute + 共享内存（Workgroup Shared Memory）融合管线，与 Unity 内置（URP Bloom）的光栅化 Blit 链形成鲜明对照。证据：CS 126528（E5267/E5291 等中间级）的反汇编。

4.8.1 该引擎 Bloom 的技术清单（全部反汇编实锤）

  • ① 单 Dispatch 融合 H+V 双向高斯：CS 126528 在一次 dispatch 内完成水平+垂直两次模糊——每个 workgroup（8×8 线程）先把 16×16 纹素块加载进 3 个共享内存数组（uint[128]×3，RGB 各一），ControlBarrier 后做水平高斯，再 ControlBarrier 做垂直高斯，最后 ImageWrite 写出。Unity URP 的等价操作需要两个独立 Blit pass（水平 RT → 垂直 RT），本实现省掉一次中间纹理的写+读往返。
  • ② 共享内存半精度打包：加载阶段用 PackHalf2x16 把两个 half 压进一个 uint（3 通道 × 128 uint = 1.5KB workgroup 内存），共享内存占用减半，直接提升 occupancy。
  • ③ 9-tap 二项式高斯核：权重 0.2734 / 0.2188 / 0.1094 / 0.0313 / 0.0039 逐位对应二项式系数 [70, 56, 28, 8, 1]/256（即 [C(8,4),C(8,3)...]/2⁸）——精确的对称 9-tap Gaussian，质量高于 URP 默认的双线性降采样。
  • ④ 每线程 2×2 纹素加载：加载阶段每线程采样 4 个纹素（(0.5,0.5)/(1.5,0.5)/(0.5,1.5)/(1.5,1.5)），8×8 线程组覆盖 16×16 输入块，为模糊提供 4 纹素 halo。
  • ⑤ Karis 亮部提取（CS 126477，首轮已确认）：4 对角 tap + NaN/Inf 防护 + 1/(luma+1) 抗闪烁加权——Unity URP 的 Prefilter 只是简单 threshold 减法，无 Karis 加权。
  • ⑥ FMix 金字塔混合（CS 126533）：升采样时 fetch(低级) + sample(高级) → FMix(intensity)，单 dispatch 完成合并。

4.8.2 对比 Unity 内置 Bloom（URP）

维度本引擎（终末地）Unity URP Bloom差距
执行方式纯 Compute（ImageWrite）光栅化 Blit（全屏三角形）省去光栅化/三角形开销，无 RT 绑定切换
每级模糊 pass 数1 个 dispatch（H+V 融合于共享内存）2 个 Blit（H→中间RT→V）每级省一次纹理往返，移动端带宽敏感场景收益显著
滤波核9-tap 二项式 Gaussian（/256 精确权重）双线性降采样（BlurH/BlurV）或 Dual Kawase核更大更平滑，质量更高
亮部提取Karis 软阈值 + 1/(luma+1) 抗闪烁 + NaN 防护简单 threshold（soft knee），无抗闪烁加权抗闪烁更好（Karis 为 ACES/CoD 方案）
共享内存PackHalf2x16 压缩（1.5KB/wg）不适用（无 compute）—
金字塔层数2 级（921×518 → 461×259，共 15 dispatch）可配 5–8 级 mip层数少 = bloom 半径小但省带宽，移动端取舍合理
评价：这是一套面向移动端带宽的 Compute Bloom——用共享内存把每级的 H+V 模糊压进一次 dispatch、用半精度打包压缩共享内存、用精确二项式核保证质量，同时亮部提取用了比 Unity 更讲究的 Karis 加权。15 个 dispatch 完成整条金字塔（1842×1036→921×518→461×259 两级），是"少层数+高质量核+零中间纹理"的移动端最优解之一。唯一取舍是金字塔只有 2 级，bloom 扩散半径比 Unity 默认（5+ 级）小。

6. 优化建议

建议 1（overdraw）：植被与小实例物件是首要优化点。E3714（1860×17）、E4096（48×39）等高实例数 Draw 位列耗时榜首，且植被在 Depth Pass #4、GBuffer Subpass 2 中被多次绘制。可考虑：植被 LOD/密度随距离衰减、Alpha-test 改 Alpha-to-coverage 减少 PS 深/浅分支、以及评估 E3120/E4573 这类 1536×62 实例的屏幕覆盖率。
建议 2（阴影渲染开销，原"深度冗余"结论作废重评）：重取证表明 Depth-only Pass #1–3 是阴影图渲染（聚光 512² + CSM 2048²/3072×2048，~426 Draw），并非被丢弃的场景深度——不存在浪费。真正的优化点：①CSM 两 cascade 分别清屏且逐物体重绘，可评估 GPU 剔除后的 cascade 共享绘制列表或合并 pass；②聚光阴影仅 21 Draw 但独占一个 RP，若灯数少可合入 CSM 末级 atlas。另：Compute Pass #1（98 action）为 RenderDoc 回放注入，真机帧中不存在，勿计入性能结论。
建议 3（Subpass 4 重复着色）：37839/33729/29655 级别的大网格在 Subpass 4 被整体重绘（E4256 耗时 0.061ms）。若用于水/反射，建议以屏幕空间 mask（Stencil 或深度范围）限制重绘范围，或降半分辨率渲染后上采样。
建议 4（Draw 数量）：整帧 1126 Draw 中约 560 个集中在 4 个深度预pass。顶点拉取架构下可进一步把多段深度预pass合并为单次间接绘制（Multi-Draw Indirect），并复用帧首剔除结果；Depth Pass #2 的 ~290 个 Draw 与 GBuffer Subpass 1 的 ~330 个 Draw 几何高度重叠，确认 prepass 的 Early-Z 收益是否大于其成本。
建议 5（回读阻塞）：帧尾 vkCmdCopyImageToBuffer(E5620) 触发 BackBuffer 回读，会打断与下一帧的并行。若非必须（截图/水印），建议移除或改为异步、隔帧执行。
