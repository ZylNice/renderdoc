棋盘渲染完整分析（EID 349）

0. 这个 draw 是什么

EID 349 是棋盘本体：一张 90 索引的低面数平面/浅壳网格，在主场景 pass（Colour Pass #2）前段绘制，直接写入全分辨率主场景 RT 80804——这张 RT 随后就是泛光链（EID 7063 起）的输入 _u_BloomSrcTex。英雄、特效都画在它之上。同家族另有变体：76521（EID 1804，27942 索引，输出去其他 RT）与 80667（EID 1716，21915 索引，带 VS 顶点波动画的道具）。

1. 渲染管线

1.1 顶点着色器（VS 76524）

极简：只有 _u_MainTex_ST + ObjectToWorld/VP/W2O 矩阵。向 PS 传一路 vec4 varying vs_TEXCOORD0：xy = 第一套 UV，zw = 第二套 UV（经 ST 变换），供 PS 按开关分别选用。无任何顶点动画（波动画是变体 80666 的事）。

1.2 像素着色器（PS 76525）执行链

① 双 UV 选择→ ② 双贴图采样→ ③ 逐格点亮 lerp→ ④ 战斗状态提亮（GameState==1）→ ⑤ 染色 + alpha 裁剪→ ⑥ 屏幕空间暗角（反射门控）→ 输出

① 双 UV 选择

uvMain = _u_MainTexUse2UV ? vs_TEXCOORD0.zw : vs_TEXCOORD0.xy uvLightOn= _u_Use2UV ? vs_TEXCOORD0.zw : vs_TEXCOORD0.xy // 主图与点亮层可各自独立选择 UV 集（第二套 UV 通常用于不同平铺/对齐方式）

② 双贴图采样

main = tex(_u_MainTex, uvMain) // 1024²（76966）：熄灭态棋盘 lightOn = tex(_u_LightOnTex, uvLightOn) // 1024²（76967）：点亮态棋盘 // ★ lightOn.a = 逐格点亮阈值 mask

③ 逐格点亮系统

t = (_u_ChangeValue >= lightOn.a) ? 1.0 : 0.0; // 全局进度 vs 每格阈值 if (_u_IsSmoothChange != 0) t = _u_ChangeValue; // 平滑模式：整板连续渐变 color = lerp(main, lightOn, t); // 熄灭格 → 点亮格
机制：LightOnTex 的 alpha 是美术刷的"点亮时刻表"（每格一个灰度=点亮时机）；_u_ChangeValue 是 CPU 每帧推进的 0→1 全局时钟。时钟扫过阈值时格子依次亮起——硬阶跃模式逐格跳变，平滑模式整板交叉淡化。

④ 战斗状态提亮（仅 GameState==1）

if (_u_GameState == 1) { uvL = _u_LightenTexUse2UV ? vs_TEXCOORD0.zw : vs_TEXCOORD0.xy; color.rgb = lerp(color.rgb, tex(_u_LightenStateTex, uvL).rgb, _u_StateChangeValue); } // _u_LightenStateTex = 1024²（76965）：战斗态整板提亮/变色图 // _u_StateChangeValue = 0→1 的切换进度（平滑过渡，非跳变）

⑤ 染色与 alpha 裁剪

color *= _u_Color; // 整体染色 alpha = color.a × _u_MainAlpha; if (_u_IsAlphaTest && alpha - _u_CutOffValue < 0) discard; // 镂空裁剪（缝隙/花纹）

⑥ 屏幕空间暗角（前向、反射门控）

if (_u_Vignette_Params2.z > 0) { // 强度>0 才启用 sUV = gl_FragCoord.xy / _ug_ScreenParams.xy; // 屏幕 UV（ProjectionParams.x 控 Y 翻转） d = abs(sUV - Params2.xy) × Params2.z; // Params2.xy=中心, z=强度 d.x *= Params1.w; // XY 比例校正 v = pow(max(1 − dot(d,d), 0), Params2.w); // 径向衰减，w=幂次 vig = lerp(Params1.rgb, vec3(1), v); // 中心白 → 边缘 Params1.rgb color.rgb = (_ug_EnableBlurReflection ≤ 0.5) ? color.rgb × vig : color.rgb; }
暗角是前向逐像素算在棋盘 shader 里的（非后处理），只压棋盘、不压英雄特效。且被 _ug_EnableBlurReflection 门控：开模糊反射时跳过——反射 RT 中已含暗角，避免压两次。

输出

SV_Target0 = vec4(color.rgb, alpha) → RT 80804（主场景）+ 深度 80805 // alpha = MainTex.a 经点亮 lerp 后 × _u_Color.a × _u_MainAlpha

3. 结论要点

1) 棋盘是单 draw 低模平面（30 三角形），所有表现都在 PS 内完成：点亮动画、状态切换、 裁剪、暗角四合一，无额外 pass 2) 两套"时间轴"互不干扰：_u_ChangeValue 管逐格点亮（对 LightOnTex.a 阈值扫动）， _u_StateChangeValue 管战斗态提亮（GameState==1 时的整体 lerp 进度） 3) 暗角在前向 shader 内、屏幕空间、且被模糊反射开关门控 4) 输出 RT 80804 是泛光链的直接输入——棋盘点亮/提亮的高亮区域会成为 Bloom 亮斑源 5) 同族三 shader（76525/76521/80667）共享常量布局与 PS 逻辑，差异在纹理配置与 VS （80666 额外带 RippleFreq/Strength 顶点波动画）
