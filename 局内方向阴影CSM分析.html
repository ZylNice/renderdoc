局内方向阴影（CSM）分析

截帧：局内-有泛光.rdc（OpenGL） · 王者万象棋 · 基于 RenderDoc 抓帧逐事件分析 · 2026-09-21
结论：方向阴影（CSM）在局内只服务于场景/地图静态物件，英雄用的是另一套 blob 投影阴影。 CSM 阴影图为隔帧/按需更新（10 draw 深度渲染 + 每帧 7 个 draw 的 4-tap PCF 采样），摊薄成本很低。 因此关掉它省不了多少性能，但会丢场景投影观感；真要省，必须用 shader keyword 剥离变体—— 现有的 _u_UseDirShadow 开关是 uniform Select，关了也照样采样，不省钱。

一、局内其实有两套互不相干的阴影系统

① 英雄 blob 投影阴影（每帧都渲染） 遮罩 pass（20~34 个 draw）：把英雄剪影以恒定强度 _ug_HeroShadowIntensity 渲进 512×512 R8 纹理，无深度附件； 再经全屏 4-tap 加权模糊生成最终 HeroShadowTex， 由 HeroShadowProjector shader（如 EID 2447）按投影矩阵贴回地面。
② 方向光 CSM 阴影（隔帧/按需更新） Depth-only Pass：10 个 draw 把场景网格（不含英雄）以 DepthBias + ShadowPancaking caster shader 渲进 1024×1024 D16 深度图 Texture 296207。有泛光帧整帧无此 pass、无泛光帧完整出现 → 并非每帧渲染。

3. 像素 shader 中的 CSM 采样逻辑（SPIR-V 反汇编还原）

// 法线偏移后用 CSM 矩阵投影世界坐标
shadowPos = g_CSMShadowMatrices * (worldPos + normal * normalBias);
fade = clamp(shadowPos.z * CSMDistanceFade.x + CSMDistanceFade.y, 0, 1);
if (fade < 1.0) {                        // 距离淡出：远于阴影距离直接跳过
    ndc = shadowPos.xyz / shadowPos.w;
    if (abs(ndc.xy) < 0.9922) {          // 阴影图包围盒内才采样
        // 双线性权重 4-tap 硬件 PCF（ImageSampleDrefExplicitLod × 4）
        s = w0*texCmp(uv0,d) + w1*texCmp(uv1,d) + w2*texCmp(uv2,d) + w3*texCmp(uv3,d);
        shadow = s * 0.0625;              // 权重归一
        shadow = fade*(1-shadow) + shadow;
    } else shadow = 1.0;
} else shadow = 1.0;

shadow = (_u_UseDirShadow != 0) ? shadow : 1.0;   // ← 注意：Select，不是分支！
directLight *= shadow;
关键点：最终结果用 Select 赋值而非 if 包住整段采样—— 即使运行把 _u_UseDirShadow 置 0，上面 4 次 PCF 比较采样照样执行，结果只是被丢弃。 也就是说这个开关不能省 GPU 采样开销，只能改画面。

4. 英雄 shader 完全不依赖 CSM

英雄材质（如 EID 529，8982 索引）的 PS 只绑定 MainTex + 2 张参数图，常量只有 _ug_HeroLightDirection / _ug_HeroLightIrradiance，无任何阴影图采样。 英雄的地面影子来自 blob 投影（EID 2447：lerp(HeroShadowColor, 1, tex.x)）。

三、方向阴影的开销账本（本帧实测）

成本项数值频率
CSM 渲染 pass10 draw / 约 7.5 万索引（仅场景网格，空 PS）隔帧/按需更新，摊薄 ≈ 5 draw/帧
CSM 采样7 个场景 draw，每个 4-tap 硬件 PCF每帧
阴影图显存1024×1024 D16 ≈ 2 MB常驻
对比：blob 阴影生成 + 模糊20~34 draw 渲 512² R8 遮罩 + 2 个全屏模糊 draw每帧都跑

CSM 渲染虽然存在，但隔帧更新摊薄后成本仍低于每帧都跑的 blob 阴影链（遮罩 + 模糊 + 投影）。

四、能不能不要？分三个层面回答

Q1. 为什么局内还开着方向阴影？

  • 它负责场景静态物件（建筑、装饰物、地形起伏）投向地图地面的长阴影，是局内地面层次感和光源方向感的主要来源；
  • blob 阴影只能给英雄脚下一个圆形软影，无法替代场景投影；
  • 引擎侧已做了隔帧/按需更新 + 距离淡出 + 包围盒剔除，说明项目已经优化过这块。

Q2. 直接关掉（QualitySettings / _u_UseDirShadow=0）会怎样？

画面性能
运行时置 0 场景静态投影消失，地面变「平」，只剩英雄脚下圆影 几乎无收益：Select 语义下 7 个 draw 的 4-tap PCF 仍执行；只省阴影图更新（本来就是低频）和 2MB 显存
shader keyword 剥离（如 NO_DIR_SHADOW 变体） 同上 真正省掉 7 个 draw 的采样 + 矩阵/bias 计算；建议在低端机型画质档使用

Q3. 建议

  • 保留中高端档：CSM 已是缓存形态，每帧成本极低，视觉收益明确，不建议砍。
  • 低端档可选关闭：务必走 shader keyword / 变体剥离 而不是 _u_UseDirShadow 开关，否则白关。
  • 顺带修正：_u_UseDirShadow 的 Select 写法建议改为 uniform 分支包裹采样段，或直接用 keyword，避免「关了还采样」的隐性浪费。
  • 更值得优化的是 blob 阴影：20 个 draw 每帧渲 512×512 遮罩，可评估合并批次或降低更新频率（英雄不动时跳帧更新）。
